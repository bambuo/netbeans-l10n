# netbeans-l10n

Localization of Apache NetBeans. Translations are delivered as *locale overlay
JARs* (`modules/locale/<code-name-base>_<locale>.jar`) — nothing in the
NetBeans source tree is modified.

## Layout

```
netbeans-l10n/
├── l10n/                  translation trees, one directory per locale
│   ├── zh_CN/             Simplified Chinese, current master layout
│   │   └── <cluster>/<module>/src/<package>/Bundle_zh_CN.properties
│   ├── de/ ja/ fr/ …      other locales, same layout as zh_CN
│   └── legacy/<locale>/   quarantined files of modules that no longer ship
│                          (git-ignored, rebuilt by tools/migrate_locales.py)
├── modules/               language-pack build modules
│   ├── zh_CN/             Maven module producing the zh_CN .nbm
│   ├── cs/                legacy Ant template modules
│   └── de/
├── harness/               legacy Ant build assets (l10nantext, antsrc, …)
├── tools/                 build and maintenance tooling
│   ├── paths.py           single place where paths are defined
│   ├── check_missing.py   report untranslated keys
│   ├── apply_translations.py  write translation batches into the tree
│   ├── harvest_built.py   harvest keys that only exist in built jars
│   ├── gen_cnb_map.py     regenerate the module code-name-base map
│   ├── migrate_locales.py align another locale's tree with the zh_CN layout
│   ├── validate_tree.py   guard against code-consumed values being translated
│   ├── dist_locale_jars.py    place locale JARs into an assembled IDE
│   ├── build_dmg.sh       assemble a drag-and-drop macOS DMG
│   └── translations/      translation batches (trans*.tsv)
├── data/                  generated reports (git-ignored)
└── dist/                  built .nbm / .dmg (git-ignored)
```

## Build the zh_CN language pack (.nbm)

```bash
cd modules/zh_CN
mvn clean package
# -> target/nbm/org-apache-netbeans-l10n-zh-CN-1.0.nbm
```

Install with **Tools ▸ Plugins ▸ Downloaded ▸ Add Plugins**.

During `compile` the module runs `org.netbeans.l10n.LocaleJarGenerator`, which
scans `l10n/zh_CN/` (a symlink to `../../l10n/zh_CN`) and writes one overlay JAR
per module: `modules/locale/<code-name-base>_zh_CN.jar`. The real
code-name-base comes from `src/main/resources/cnb-map.properties`, generated by
`tools/gen_cnb_map.py` from a built IDE — a module's directory name alone is not
always its code-name-base (`core.ui` is `org.netbeans.core.ui`).

## Build a macOS DMG (arm64)

Requires the IDE to be built first (`ant build` in the NetBeans checkout, output
in `nbbuild/netbeans`).

```bash
tools/build_dmg.sh
# -> dist/Apache-NetBeans-arm64.dmg
```

The DMG bundles the IDE plus every locale JAR, uses the native Swift launcher,
and patches `platform/lib/nbexec` so the IDE also finds user-level JDKs
(`~/Library/Java/JavaVirtualMachines`) when started from Finder.

## Translating

1. Add the new strings to a batch file under `tools/translations/`
   (`<english value>` TAB `<translation>`, one per line).
2. Apply it and rebuild:

```bash
python3 tools/apply_translations.py    # rewrites still-English values
python3 tools/validate_tree.py         # guard: numbers/literals/merged keys
python3 tools/check_missing.py zh_CN   # report -> data/missing_zh_CN.json
```

`apply_translations.py` never touches values that code consumes literally —
pure numbers (`390`, parsed with `Integer.parseInt`) and keywords compared with
`==` (`default`, `true`, `always`, …) — because translating them breaks the UI.
`validate_tree.py` re-checks the whole tree for exactly that class of damage,
plus values that accidentally swallowed the next key (`--fix` restores English).
Run it after every batch; it exits non-zero when something is wrong.

## Legacy Ant modules (`modules/cs`, `modules/de`)

These drive the old `Package.java` pipeline via `harness/build.xml`. They need a
`nbbuild` directory from a NetBeans monorepo checkout and are kept for
reference; the Maven pipeline above is the supported path.

To add a new language with the legacy pipeline, copy `modules/de`, rename it,
and change `locale`, the module names in `manifest.mf` and the bundle directory
under `src/org/apache/netbeans/l10n/`. Build `harness/l10nantext` first.
